# Release test-to-branch-effect map

This map names the observable effect protected by each release check. A test is
not credited merely because it executes a branch. Curriculum checks resolve
skills through canonical manifest fields or declared capabilities, never
through a historical skill code, title fragment, or fixed catalog size. The
mutation runner separately proves representative families are non-vacuous.

| Test | Protected branch effect |
|---|---|
| `CORE-00` | The canonical curriculum manifest parses, validates, and satisfies its declared counts, ordering, references, and acyclic prerequisite graph. |
| `MANIFEST-CLOSED` | Unknown fields at the manifest root or in localization, licensing, authorship, review, phase, policy, schema, band, level, rationale, source, benchmark, skill, assessment, or constraint records are rejected instead of silently entering the public release contract. |
| `CORE-01` | Duplicate or moved engine markers, or any change to marked engine bytes, changes extraction or SHA-256. |
| `CORE-02` | Removing a stable public API entry point makes the engine contract incomplete. |
| `CORE-03` | Adding a prohibited ambient identifier makes deterministic-engine purity fail. |
| `BEH-01` | The runtime manifest object, version, ordered levels and skills, and exact manifest SHA-256 match the canonical versioned artifact. |
| `BEH-02` | Every declared `generatorProfile` produces deterministic, distinct, answerable work through at least one manifest-selected skill. |
| `BEH-03` | Each runtime skill preserves the manifest's prerequisites, mastery role, CPA phases, representation, family, profile, and constraints. |
| `BEH-04` | Adult, daily, fatigue, and time truncation change the effective limit and stop classification independently of a natural session. |
| `BEH-05` | Every stop path retains exactly one `NON_EVIDENCE` capstone and completes any active re-teach first. |
| `BEH-06` | The manifest band's configured pick cadence is applied and every offered card is meaningfully distinct while preserving the same learning obligation. |
| `BEH-07` | Every declared selection or construction method can physically enter a correct generated answer, including model-based and exact rational or decimal targets where assigned. |
| `BEH-08` | Mastery, re-teaching, demotion, gateway pull-back, and promotion branches remain independently observable under the locked progression rules. |
| `BEH-09` | Hint use, deliberate answer change, first-answer miss, and invalid telemetry each leave the clean-feedback branch. |
| `BEH-10` | Repeated seeded generation is byte-equivalent and input state remains unchanged. |
| `BEH-11` | A network API or remote runtime resource in the shipped page is rejected. |
| `BEH-12` | Export and import preserve canonical schema-2 state plus exact manifest identity and digest. |
| `BEH-13` | Port 8771, the `math-quest-local-server:v1` health contract, and gameplay storage `math-quest:v2` remain distinct; the launcher binds only to loopback. |
| `BEH-14` | Unknown child-string records, prompt-template drift, customary measurement, or non-Canadian money in governed contexts is rejected. |
| `BEH-15` | Forbidden rewards, traits, and superlatives fail only in scoped child-facing categories. |
| `BEH-16` | Removing a required machine-checkable model from any applicable manifest-selected capability identifies the affected skill. |
| `BEH-17` | Removing a required neutral research, provenance, privacy, or release artifact fails the governed-artifact check. |
| `BEH-18` | Equal finite decimals normalize exactly, malformed forms fail, and manifest-selected decimal operations remain reachable from their assigned input method. |
| `BEH-19` | Adult item cap, adult time cap, and remaining daily allowance each constrain and survive save round-trip. |
| `BEH-20` | Duplicate samples do not strengthen mastery; `NON_EVIDENCE` does not revoke fast track. |
| `BEH-21` | An unsolid prerequisite blocks ordinary practice while every level declared by the manifest remains previewable. |
| `BEH-22` | Active level re-teaching blocks promotion and cannot clear without new recovery evidence. |
| `BEH-23` | A rapid clean selection resets the guessing-like streak without offering a fatigue stop. |
| `BEH-24` | Normalized duplicate or exhausted feedback pools fail their capacity branch. |
| `BEH-25` | Any approved child-facing string record change changes its canonical SHA-256. |
| `BEH-26` | Preview application preserves earned level and all skill evidence. |
| `BEH-27` | Unknown, non-finite, malformed, old-schema, or wrong-manifest imports reject without mutating live state. |
| `BEH-28` | Candidate play days advance or stay equal, but clock rollback cannot lower `maxSeenPlayDay`. |
| `BND-01` | Seven clean results in the latest 12 activates level re-teaching; eight does not. |
| `BND-02` | Exact 0.80 promotion succeeds with solid gateways and fails with one gateway unsolid. |
| `BND-03` | A selection change at 599 ms is ignored; 600 ms is deliberate. |
| `BND-04` | Every spacing-index advance, reset, final repeat, and overdue case is based on the actual review day. |
| `BND-05` | Structurally eligible non-clean evidence revokes fast track; `NON_EVIDENCE` does not. |

## Manifest semantic effect map

The semantic suite contributes exactly 130 result records: one load/binding
check, one taxonomy check, one check for each of 126 skills, and two
task-type/mastery checks. A green release run must also reconcile 126 skills,
156 declared task types, and 6,048 deterministic generated questions.

| Test | Protected semantic effect |
|---|---|
| `SEM-CORE` | The shipped engine and canonical manifest both load, and the embedded manifest bytes and SHA-256 exactly match the canonical artifact. |
| `SEM-TAXONOMY` | Every skill has identical manifest generation task types, manifest mastery task types, and runtime task types; the explicit 126-skill semantic signature table is complete. |
| `SEM-MQ-001` … `SEM-MQ-126` | For the named skill, both tiers across the deterministic ordinal cycle cover every declared task type and only its approved prompt/model signature; generation repeats exactly, prompt slots resolve, input and model descriptors are truthful, the answer self-grades, and answer submission preserves the task type. The facet checks additionally require both tenths/hundredths, all four remainder interpretations, both unit-cube/layer volume representations across the declared units and solids, and both 12-/24-hour timetable formats. |
| `SEM-MASTERY-COVERAGE` | A multi-task-type skill cannot become `SOLID` until clean, otherwise-qualified evidence witnesses every required task type. |
| `SEM-INVALID-TASK-TYPE` | An undeclared attempt task type is rejected with `REJECTED_ATTEMPT_TASK_TYPE` and cannot append evidence. |
| `node:test` semantic-module import | Native coverage dynamically imports the semantic suite, verifies its exported runner, and requires the exact 130/126/156/6,048 result totals before accepting the engine coverage run. |
| `SAVE-VALID` / `SAVE-REJECT` | Native coverage accepts valid question, construction, pick, feedback, capstone, fatigue, legacy, and inactive snapshots, then independently rejects every malformed root field, skill record, settings field, active-session field, question field, attempt field, and resumable-UI discriminator. A nested invalid snapshot also proves transactional import and throwing export without mutating live state. |
| `API-PARSE` / `API-GRADE` / `API-SUBMIT` | Public parsing, grading, and submission APIs distinguish malformed, equivalent, wrong, normalized, defaulted, reduced-choice, named-candidate, construction, rapid, and invalid-telemetry inputs by asserting their exact canonical result, evidence class, feedback class, or telemetry status. |
| `API-PROGRESSION` / `API-FATIGUE` | Public spacing, fast-track, level re-teaching, promotion, repeated-miss, fatigue, stop-classification, feedback, and child-string branches are checked through exact state, signal, target, and returned-text effects. |
| `API-STATE` | Defensive load/apply/queue paths assert rejected-attempt effects, non-evidentiary isolation, task-type fallback or rejection, cap enforcement, gateway pull-back, restoration, promotion, level re-teach clearing, due-review representation, preview isolation, and empty-session results. |
| Native coverage calibration | A full two-way fixture must report 100%, a partial fixture must report less than 100%, and two complementary evaluations of identical bytes under one virtual filename must aggregate to 100%. The exact staged engine URL, root source span, and V8 range map are then required before its calibrated native branch percentage can gate release. |

## Exhaustive generator effect map

The exhaustive gate evaluates 72,576 deterministic question instances across
all 126 skills, both tiers, every declared task type, and a broad seed/ordinal
matrix. It also performs 40,824 independent question-choice searches. In the
frozen review, 37,440 searches produced valid distinct pairs and 3,384 were
legitimately suppressed because the learning obligation had no meaningfully
different second sample.

| Check | Protected generator effect |
|---|---|
| Deterministic replay | Identical inputs reproduce byte-equivalent questions, while the audited seed/ordinal matrix reaches every declared task type. |
| Self-grade and input reachability | Every generated correct answer passes the shipped grader and can be entered through the assigned selection or construction control. |
| Constraint and model truth | Generated values, prompt slots, answers, and semantic model descriptors remain within the skill's closed manifest constraints and describe the same mathematical object. |
| Question-choice search | A two-card choice appears only when two distinct samples preserve one obligation; invariant tasks suppress a false choice. |
| Answer-position distribution | The correct slot uses a context-hashed, low-discrepancy 32-bit Weyl sequence for two- and four-option work and a context-rotated base-3 digit sequence for three-option work; each sufficiently sampled task/prompt/arity context uses the required number of positions and no position exceeds 75% of its samples. |

## Representative mutation proof

`audit/mutation-runner.mjs` creates disposable copies under the operating
system's temporary directory. It alters one effect in each required family and
runs only the protecting test. The mastery/promotion family also contains a
nested task-type-coverage mutant, so the eight families kill nine
effect-sensitive cases. A family passes only if its baseline test passes and
all of its mutants fail. The shipped `index.html` is never edited.
